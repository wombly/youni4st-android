# Youni4st 0.7.0 — что сделать после установки

## 1. Установи APK поверх 0.6.9

Подпись APK сохранена, удалять старое приложение и очищать его данные не нужно. В сборку включён обновлённый `google-services.json` из твоих исходников. В готовой APK 0.6.9 этого Google OAuth-клиента ещё не было.

## 2. Обнови правила базы — это обязательно для облачного сохранения

Ранее опубликованные правила разрешают только регистрацию никнеймов. Для профиля, резюме и избранного добавлена отдельная закрытая коллекция.

1. В Firebase выбери проект Youni4st → Cloud Firestore → база `(default)` → Rules.
2. Открой файл `firebase/firestore.rules` именно из исходников **0.7.0**.
3. Скопируй всё его содержимое. В редакторе Firebase замени прежний код полностью.
4. Нажми **Publish / Опубликовать**.

Этот файл сохраняет правила никнеймов и добавляет правила личных данных. Новые коллекции вручную создавать не нужно. Если в вашей базе дополнительно существуют другие функции с собственными правилами, их нужно сохранить при объединении.

Пересобирать APK после публикации правил не требуется. В приложении открой Профиль → «Синхронизировать».

## 3. Проверь перенос на другой телефон

1. На первом телефоне войди в аккаунт. Открой профиль, сохрани данные, добавь вуз в избранное и заполни резюме.
2. В профиле дождись сообщения **«Данные синхронизированы с аккаунтом»**.
3. На втором телефоне установи эту же версию и войди **в тот же аккаунт тем же способом**.
4. Профиль, резюме с фото, избранное, черновики, история чата и настройки восстановятся из облака. PDF можно скачать заново из восстановленного резюме.

Файлы, ранее экспортированные в «Загрузки», не копируются — синхронизируются данные, по которым приложение формирует PDF. История чата хранит последние 40 сообщений. Фото в облачной копии уменьшены до 512 пикселей по длинной стороне; оригинал на первом телефоне не изменяется.

Без интернета изменения сохраняются на телефоне и остаются в очереди. Приложение повторяет отправку при восстановлении сети, открытии приложения или нажатии «Синхронизировать». Если приложение полностью закрыто, очередь будет продолжена при следующем запуске. Перед входом на новом устройстве убедись, что первый телефон успел отправить изменения.

Для чтения новых изменений на уже открытом втором телефоне вернись в приложение или нажми «Синхронизировать». Постоянного опроса базы каждую секунду нет. Изменения избранного с разных устройств сохраняются по отдельным пунктам. При одновременном редактировании одного профиля или одного резюме используется последняя успешно записанная версия раздела.

## 4. Как Google и телефон могут открывать один аккаунт

Сначала войди основным способом, например через Google. Затем открой **Профиль → Способы входа** и привяжи номер телефона. После подтверждения оба способа открывают один Firebase UID и одну облачную копию.

Если раньше отдельно зарегистрированы два аккаунта — один Google, второй по телефону — это могут быть разные Firebase UID. Они не объединяются автоматически. Приложение сообщит, что способ входа уже занят другим аккаунтом; чужие и отдельные данные не смешиваются.

Google-входу нужны Google Play services и Google-аккаунт на телефоне. Новый JSON уже содержит веб-клиент OAuth и SHA-1 сертификата нашей APK; повторно заменять его перед этой сборкой не требуется.

## 5. Если SMS не приходит

1. Firebase → Authentication → Sign-in method: Phone должен быть включён.
2. Authentication → Settings → SMS region policy: разреши Казахстан.
3. В Project settings → Android-приложение должны быть сохранены SHA-1 и SHA-256 из `APK-СЕРТИФИКАТ.txt`.
4. При появлении reCAPTCHA заверши проверку в браузере и вернись в приложение. Код проверки теперь восстанавливает обработчики после возврата.
5. Запрос повторной SMS доступен через 60 секунд. Лишняя цифра не сдвигает номер; старые обработчики не могут переключить уже выбранный другой аккаунт.
6. Лимиты SMS, доступность регионов и требования оплаты определяет Firebase. Код `ERROR_BILLING_NOT_ENABLED` означает, что для реальных SMS нужно отдельно настроить оплату. Включение оплаты в эту работу не входило и автоматически не выполнялось. Google и e-mail можно использовать отдельно от SMS.
7. Для проверки без реальной SMS в Firebase есть тестовые номера и коды. Используй их только для тестирования, не включай фиксированный код в исходники приложения.

Если ошибка остаётся, пришли её код в квадратных скобках. Реальную доставку SMS и вход в твой Google-аккаунт без телефона проверить с этого компьютера нельзя.

Официальные инструкции: https://firebase.google.com/docs/auth/android/phone-auth и https://firebase.google.com/docs/auth/android/google-signin

## 6. Как изменён запуск

Первый кадр самого приложения рисует лёгкий нативный экран с логотипом и надписью **до** инициализации Compose, Firebase и каталога. Затем экран продолжается анимацией без повторной вибрации. Время показа — примерно две секунды от первого кадра приложения. Константа `INTRO_DURATION_MS = 2000` находится в `StartupSettings.kt`.

У системного логотипа Android нет искусственного таймера удержания. До запуска процесса им управляет сама ОС; её время нельзя гарантированно обнулить кодом приложения. Для уменьшения накладных расходов подготовлена сборка release с удалением неиспользуемого кода и ресурсов. Точное время от нажатия на значок нужно измерять на конкретном телефоне.

Вибрация длится 280 мс и затухает. Она не блокирует загрузку. Остальные пользовательские тексты баннеров и переносы строк сохранены.

## Где хранятся данные

Все облачные данные относятся к Firebase UID. Коллекции `handles` и `usernames` обеспечивают уникальность никнейма, а `user_data/{uid}` хранит личную копию. Правила запрещают читать и менять данные другого UID. Данные разных аккаунтов разделены и на телефоне.

Для небольших фотографий используется тот же Cloud Firestore; отдельный платный Cloud Storage bucket не нужен. Ограничения бесплатного тарифа Firebase продолжают действовать: https://firebase.google.com/docs/firestore/quotas

В живой облачной базе правила не публиковались автоматически. В проекте приложены готовые правила и локальные тесты их безопасности.
