# Как менять содержание и подключать сервисы

Все пути ниже указаны относительно папки проекта `youni4st-android`.

## Картинки, логотипы и фотографии

Создай `app/src/main/assets/images/` и положи туда PNG/JPG/WebP, например `aitu.png`, `company.png`, `mentor-alex.jpg`. Имена — латиницей без пробелов. Для логотипов удобен квадратный прозрачный PNG; для наставников — портрет 600×600. Приложение вписывает логотип, а фотографию обрезает по форме карточки.

В нужной записи каталога укажи:

```json
"logo_url": "images/aitu.png"
```

Для наставника поле называется `photo_url`:

```json
"photo_url": "images/mentor-alex.jpg",
"profile_url": "https://ВАША-ПЛОЩАДКА/ПРОФИЛЬ",
"platform": "Название площадки",
"languages": {"RU": "Русский, казахский", "KZ": "Орысша, қазақша", "EN": "Russian, Kazakh"}
```

Вместо локальной картинки можно указать публичный HTTPS-адрес. При отсутствии или ошибке картинки отображается аккуратная тематическая иконка. Подставляй настоящие изображения с правом использования: вымышленные лица не выданы за реальных наставников. `profile_url` должен вести на профиль выбранного наставника; пустая ссылка отключает переход. Ссылка проверяется по формату HTTPS, а не на репутацию сайта. Поэтому текст интерфейса не обещает абсолютную безопасность внешней площадки.

Логотип самого проекта: `app/src/main/res/drawable-nodpi/brand_logo.png`. Четыре иллюстрации главной нарисованы в `ui/ModernComponents.kt`, функция `SectionArt`.

## Где менять тексты и записи

| Раздел | Файл в `app/src/main/assets/` |
|---|---|
| Вузы и специальности | `universities_db.json` |
| Наставники | `mentors_screen.json` |
| Вакансии | `jobs_db.json` |
| Программы | `edu_programs_db.json` |
| Гранты | `grants_db.json` |
| IELTS | `ielts_db.json` |
| Новости | `news_verified.json` |
| Условия и конфиденциальность | `legal.json` |
| Ссылки и настройки сервисов | `app_config.json` |

В каталогах сохранены прежние структуры RU/KZ/EN. Меняй все три перевода, сохраняя кавычки и запятые JSON. Для новой записи скопируй существующую и присвой **уникальный постоянный `id`**, например `universities:my-new-university`. Не меняй ID существующих записей и не используй их повторно: на них опираются избранное и отклики.

Контакты в записи университета:

```json
"contacts": {
  "phone": "+77170000000",
  "email": "admissions@example.com",
  "website": "https://example.com",
  "address": {"RU":"Адрес", "KZ":"Мекенжай", "EN":"Address"}
}
```

Это пример формата, не реальные контакты. Заполни своими данными. Специальности уже берутся из прежнего массива `specialties` и показываются по нажатию.

Тексты кнопок и экранов находятся в `app/src/main/java/kz/youni4st/app/ui/`. Ищи нужную русскую фразу через поиск VS Code; рядом в `t(...)` находятся казахская и английская версии.

## Поддержка, соцсети и документы

В `app_config.json` заполни `support` и `social`. WhatsApp — полная ссылка `https://wa.me/...`, Telegram — `https://t.me/...`, телефон — номер с кодом страны, email — адрес без `mailto:`. Instagram/TikTok — HTTPS-ссылки твоего проекта.

`privacy_url` и `terms_url` открывают опубликованные документы. Внутренний `legal.json` содержит описание функций тестовой версии; он не заменяет окончательные условия с данными владельца, контактами, сроками хранения и правилами удаления аккаунта. Перед включением публичной регистрации согласуй текст с фактической работой сервиса.

## Телефон, Google и E-mail

В проект встроен Firebase Authentication, но проект Firebase владельца не предоставлен. Фиктивных аккаунтов нет. После настройки приложение будет отправлять запросы в твой Firebase.

1. Создай/выбери Firebase-проект, добавь Android-приложение с package ID `kz.youni4st.app`.
2. В Authentication включи Email/Password, Phone и Google. Для SMS проверь требования к тарифу, доступным регионам и лимитам в консоли. Начинай с тестовых номеров Firebase.
3. Добавь SHA-1 и SHA-256 сертификата **той сборки, которую устанавливаешь**; для локального APK, GitHub и Google Play подписи могут различаться. Получить отпечатки своей локальной сборки можно через `gradlew.bat signingReport`.
4. Из настроек Android-приложения / скачанного `google-services.json` перенеси публичные параметры в `app_config.json`:
   - `firebase.api_key` — `api_key.current_key`;
   - `firebase.application_id` — `client_info.mobilesdk_app_id` (не package name);
   - `firebase.project_id` — `project_info.project_id`;
   - `firebase.google_web_client_id` — OAuth Client ID типа **Web**, а не Android.
5. Пересобери APK. Этот проект инициализирует Firebase вручную: добавлять Gradle-плагин Google Services не нужно.
6. Проверь SMS, Google, создание E-mail аккаунта, восстановление пароля и выход на реальном телефоне.

Номер вводится с фиксированным +7 и маской. Firebase поддерживает автоматическое подтверждение SMS на совместимых устройствах; в остальных случаях код вводится вручную. Вход не синхронизирует локальное резюме и избранное между телефонами.

Секретный JSON сервисного аккаунта Firebase Admin, приватные ключи и ключ AI в APK/репозиторий не добавляй. Android Firebase config — клиентские параметры; серверный Admin key предназначен только серверу.

Официальные инструкции: [телефон](https://firebase.google.com/docs/auth/android/phone-auth), [Google](https://firebase.google.com/docs/auth/android/google-signin), [E-mail](https://firebase.google.com/docs/auth/android/password-auth). Иконка Google загружена из официальных [материалов бренда](https://developers.google.com/identity/branding-guidelines) и не перерисовывалась.

## Отклики и AI

Для откликов нужен защищённый API, описанный в [APPLICATIONS_API.md](APPLICATIONS_API.md). Его URL задаётся в `applications_endpoint`. До подключения отправка недоступна. Наставники открываются по ссылке и не требуют API записи.

AI продолжает использовать `POST /api/chat` существующего backend. Ключ провайдера задаётся **на сервере** через `B_AI_API_KEY`; в Android он не нужен. Если сервер не отвечает, приложение показывает ошибку и повтор. Не публикуй ключ в чат, APK или исходниках.
